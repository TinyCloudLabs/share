TinyCloud HTML artifact sharing

Concrete implementation plan for encrypted, prefix-scoped HTML bundles rendered as full-page, opaque-origin artifacts through the existing verified sharing path.

SOL REVIEWED · REVISED BEFORE IMPLEMENTATION

Outcome and invariants

An addressed sender may select or upload a canonical prefix bundle with exactly one root index.html. The encrypted, signed v2 envelope carries only an optional artifact discriminator. A recipient establishes the existing policy session, lists and reads only the authorized prefix, prepares the bundle locally, and sends one self-contained document to an opaque-origin frame. Existing bearer, exact-file, and ordinary folder behavior remains unchanged.

Isolation is the feature boundary. Artifact code receives no authority material and runs without allow-same-origin, forms, popups, downloads, top navigation, storage, parent DOM access, or network access. No compatibility requirement may loosen that boundary.

Sol adversarial review and required revisions

This review challenged the initial plan before any production edit. The decisions below are incorporated into the implementation stages and acceptance tests that follow.

ChallengeFindingRevision
Security model connect-src 'none' blocks Fetch/XHR/WebSocket but does not reliably cancel a script assigning its own frame’s location; Chromium was tested and still began that request. The sandbox does prevent ancestor/top navigation. Strip every declarative navigation surface; reject direct navigation APIs in classic script sources as unsupported; include navigate-to 'none' as defense-in-depth, and destroy the artifact frame on any unexpected load. State the residual browser limit honestly: arbitrary obfuscated self-navigation cannot be proven absent, so script support is for static classic artifacts, not hostile exfiltration-resistant computation. Top-page isolation remains unconditional.
Protocol compatibility A new top-level envelope field would break strict schemas and widen every signer/binding implementation. Use only optional encrypted v2 metadata.artifact. Require encrypted === true, prefix resource, and read+list actions when present. Keep bindings and legacy envelopes byte-for-byte unchanged.
KV path and resource semantics List responses can paginate, repeat, return folder markers, contain out-of-prefix entries, or alias through normalization. Current library copying keeps only direct children. Bound pagination and cursor uniqueness; accept exact file entries only; canonicalize relative to the established prefix; reject duplicates and every out-of-prefix entry; recursively copy all listed descendants while preserving nested names and MIME.
Browser sandbox One opaque frame is enough for parent isolation, but the bridge must survive artifact document replacement and must never share an origin with artifact code. Keep the served opaque bridge plus a second opaque srcdoc artifact frame. Validate both message hops. Pin HTTP frame-ancestors headers and add a load watchdog; never add allow-same-origin, allow-forms, allow-popups, downloads, or top-navigation tokens.
Asset resolution Raw-text script serialization can terminate its own <script>; CSS imports can cycle; data URLs increase memory; a partial rewrite could accidentally render with missing dependencies. Escape case-insensitive </script in embedded classic sources, reject async/defer/module scripts, fail on CSS cycles/depth overflow, cap render aggregate at 10 MB before base64 expansion, and prepare the complete document before creating the visible frame. Revoke/clear generated resources on destroy.
UX and accessibility “Permanent” hide could trap keyboard users; a tiny visual cloud can still have an undersized hit target; status copy could expose a missing filename. Keep a 44 px semantic button even when the glyph is smaller, add a documented keyboard restore, announce transitions, support forced colors and reduced motion, and use path-free failure copy.
Failure states Silently dropping unsafe external references would produce misleading partial output. Classify malformed, missing, unsupported, denied/offline, and limit failures before frame creation. Any required unsafe/missing resource fails the whole artifact; exception text and resource paths stay out of recipient copy.
Testability jsdom does not execute sandbox documents and a mocked e2e can falsely prove only DOM assembly. Execute exported bridge scripts against a mocked window as Mermaid tests do, then use real Chromium for classic JS, relative assets, CSP network attempts, storage/parent/top isolation, frame reload watchdog, and chrome controls.
Scope Supporting arbitrary runtime-generated fetches or module graphs would require a secure virtual origin/proxy and materially widen risk. Keep modules, dynamic imports, runtime network, workers, WebAssembly, frames, forms, and artifact-triggered downloads unsupported. Controlled in-bundle HTML navigation is the only navigation feature.
Review verdict: Proceed only with the revised, bounded static-artifact model. The parent/account boundary is strong and unconditional; the documentation must distinguish that from the narrower guarantee around arbitrary obfuscated self-navigation inside a script-capable child frame.

Protocol and data shape

  • Add one optional literal field to encrypted v2 content metadata: artifact: "html". The fixed entry point is implied as index.html; no filename list, manifest, recipient data, URL, fragment, or authority material is added.
  • Keep the field absent for existing shares. Strict schemas remain additive and old signed vectors continue to parse unchanged.
  • For owner-policy shares, include the discriminator in the encrypted signed envelope only. Do not add it to public bindings, logging, analytics, history URLs, or authorization messages.
  • The signed resource remains the prefix root. The viewer derives each exact child resource by joining a canonical relative path beneath that root and invokes the existing tinycloud.kv/list / tinycloud.kv/get path.

Implementation stages

1. Artifact-bundle core

Create src/artifact/bundle.ts as the deterministic boundary for canonical paths, artifact detection, MIME fallback, query/hash-aware lookup, aggregate limits, DOM transformation, and bounded CSS resource resolution. HTML decisions use DOMParser; CSS url() and @import use bounded transformations with cycle/depth checks.

  • Canonical relative paths: NFC, forward slashes only, no empty / dot / dot-dot segments, no controls, backslashes, encoded separator/dot aliases, absolute URLs, or duplicate case-folded canonical keys.
  • Limits: 1,000 files listed, 100 MB authorized source ceiling, 10 MB render aggregate including encoded output, 5 MB per rendered text file, 16 CSS import levels, and 10,000 transformed references. Any limit failure aborts the whole render.
  • HTML transforms: stylesheets become inline styles; classic external scripts become inline classic scripts in document order; images, fonts, media, and static assets become data URLs; stylesheet media values are validated before wrapping; unsupported <link> relations fail closed; relative anchors to known HTML documents become controlled in-bundle navigation requests.
  • External URLs, protocol-relative URLs, unsafe schemes, <base>, forms, meta refresh, module/async/defer scripts, direct script navigation APIs, workers, nested frames, inline HTML event-handler attributes, and unsupported active embeds fail closed. External classic sources are embedded with case-insensitive closing-script escaping, and benign local helpers named open remain allowed so the gate only rejects explicit browser-navigation primitives.

2. Sender detection and nested path preservation

  • Preserve canonical folder-relative paths from File.webkitRelativePath, stripping exactly one common selected-folder segment. Flat multi-file selection remains compatible.
  • Recursively copy selected library prefixes instead of only direct children; preserve MIME and nested paths under the newly delegated shares/<shareId> prefix.
  • Detect an artifact only when the normalized bundle has exactly one root index.html. A normal multi-file folder without it remains a folder share and gets non-blocking guidance; unsafe/duplicate paths block creation with actionable copy.
  • Add a separate folder picker using the native directory-selection attribute while retaining the existing file picker and framework-free UI.

3. Opaque artifact frame

  • Add an app-served /artifact-sandbox.html builder and Vite output analogous to Mermaid’s proven frame.
  • Parent iframe sandbox is exactly allow-scripts. The served bridge self-checks self.origin === "null", requires a per-frame 128-bit nonce, and accepts messages only from its parent.
  • The bridge creates a second sandboxed srcdoc iframe for artifact code, also with exactly allow-scripts. Its inherited CSP allows inline classic scripts/styles and data/blob static assets but has default-src 'none', connect-src 'none', form-action 'none', object-src 'none', defense-in-depth navigate-to 'none', and no top-navigation capability. Any unexpected child load destroys the render.
  • The bridge also listens for the documented restore chord from the inner artifact frame and forwards a narrow, nonce-bound restore message to the parent chrome so permanent hide is reversible even when focus stays inside the sandbox.
  • Parent replies are checked by source window, opaque "null" origin, nonce, id, and strict shape. Destroying the controller rejects pending renders and removes the frame.

4. Verified viewer path and full-page presentation

  • After ShareRecipientClient.establishPolicySession(), detect the signed artifact marker plus prefix resource. List all entries with bounded pagination and unique cursors, canonicalize every returned file path under the established prefix, reject duplicates/folder markers/out-of-prefix paths, then issue exact get calls only for that closed set.
  • No caller-controlled URL becomes a node request. Unknown paths referenced by HTML/CSS fail as a missing-asset state before the frame receives content.
  • Artifact mode replaces ordinary folder chrome only after authorization succeeds. Loading, access denied/offline, malformed bundle, missing asset, unsupported feature, and limit failure use stable recipient-safe messages without exception text.

5. TinyCloud overlay

  • Render the artifact full viewport. A small safe-area-aware overlay outside the frame starts expanded with “Shared with TinyCloud”, collapse, share/copy, and permanently hide controls.
  • Collapsed mode is one 44 × 44 px cloud control. Permanent hide is stored as hidden under a SHA-256-derived per-share key; no URL, fragment, identity, path, or filename enters storage.
  • Restore via Alt+Shift+C, which works without pointer input and remains available after permanent hide.
  • Reshare calls Web Share first and falls back to the existing closure-held clipboard flow; the complete URL is never put in text, an href, a value, data attribute, or storage.
  • Use existing app tokens, semantic buttons, visible focus, a polite live announcement, reduced motion, forced-colors support, and pointer-independent controls.

6. Fixture, documentation, and release evidence

  • Add a small fixture with index.html, separate CSS, separate classic JS, nested SVG/image asset, nested stylesheet import, and an interactive counter plus isolation probes.
  • Add unit/integration tests at module boundaries and a Puppeteer artifact flow using the hermetic viewer path as far as the current harness supports.
  • Document supported classic static behavior, unsupported modules/runtime fetch/workers/forms/frames, restore controls, limits, and security boundary.
  • Capture desktop and mobile screenshots, inspect them, run all gates, review the diff, commit, open a PR, repair only scoped CI failures, and squash-merge only after every non-skipped check is green.

Acceptance tests

  1. Detection: one root index.html marks an artifact; missing root remains a normal folder with guidance; duplicate canonical roots and unsafe paths are rejected.
  2. Canonical resolution: nested relative references, ../ within the bundle, query/hash suffixes, CSS url(), CSS imports, src, href, srcset, and classic script sources resolve to authorized files; escapes and unknown paths fail.
  3. Limits: aggregate bytes, per-file text, file count, reference count, import depth, and import cycles terminate deterministically with no partial frame.
  4. Protocol: optional metadata round-trips in v2, remains absent in legacy shares and public bindings, and all envelope vectors plus existing single/folder tests stay green.
  5. KV authority: viewer list/get requests are descendants of the established prefix; malicious list entries and transform references cannot widen it.
  6. Sandbox: both frames omit allow-same-origin; CSP blocks Fetch/XHR/WebSocket/subresources, forms, objects, and external sources; direct self-navigation constructs are rejected and unexpected loads destroy the frame; spoofed source/origin/nonce/id messages are ignored; destroy rejects pending renders.
  7. Execution: fixture CSS, nested image/font/static asset, and classic script load; interaction works; parent DOM, storage, cookie, opener, top navigation, and fetch isolation probes fail.
  8. Viewer routing: marked prefix selects artifact mode; ordinary prefix stays folder mode; exact/bearer results are unchanged.
  9. Chrome: expanded, collapsed, reopen, permanent hide, keyboard restore, Web Share, clipboard fallback, storage denial, and URL-not-in-DOM are tested.
  10. Chrome recovery: the documented restore chord works even after permanent hide while focus remains inside the sandboxed artifact frame.
  11. Classic scripts: a local helper named open is accepted, while explicit browser-navigation primitives still fail closed.
  12. Accessibility: semantic names, focus-visible, keyboard order, live state, 44 px target, reduced motion, forced colors, and mobile safe areas are asserted or visually inspected.
  13. Failures: malformed, missing asset, unsupported feature, offline/denied, and render limit states show approved recovery copy and never exception text.
  14. Release: npm test, npm run typecheck, npm run build, and the narrowest safe sharing e2e pass; desktop/mobile screenshots are inspected; PR CI is all green before squash merge.

Explicit scope limits

Supported initially: static HTML documents, nested CSS with bounded imports, images/fonts/media/data files referenced statically, classic external and inline scripts that do not use navigation/runtime-network primitives, static relative HTML navigation through the controlled bundle router, query/hash lookup suffixes, and normal DOM interaction inside the artifact.
Unsupported by design: ES modules and dynamic imports, runtime fetch/XHR/WebSocket/EventSource, direct script navigation APIs, service/shared/workers, WebAssembly, eval, forms, popups, downloads initiated by the artifact, nested frames/embeds/objects, top navigation, cross-origin or protocol-relative resources, credentialed APIs, and server-side routing. These produce an explicit failure or are inert; none causes a sandbox relaxation. Because current Chromium still begins an iframe self-navigation despite navigate-to 'none', TinyCloud rejects direct navigation constructs and destroys unexpected loads; it does not claim to safely execute deliberately obfuscated exfiltration code.
